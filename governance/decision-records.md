# Decision records

Use a repository-local ADR for a decision that changes only one repository. Use an ADR here when the decision establishes organization policy, shared vocabulary, or a boundary spanning multiple repositories.

An ADR must include:

- status and date;
- decision owner;
- context and evidence;
- decision;
- alternatives considered;
- consequences;
- affected repositories;
- migration or adoption requirements;
- supersession relationship when replacing another ADR.

ADRs record decisions, not implementation progress. Delivery state belongs in linked issues and pull requests.
